Customization & Development

Codebase map, local development workflow, safe customization points, automated test suites, and security architecture.

Local development setup

Quiz Platform has no frontend bundler or Node build step — edit files in app/ and reload the browser.

bash
cd quiz-platform
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt pytest

# Create a local admin (data stored in ./data/)
.venv/bin/python app/manage.py create dev@example.org "Dev Admin" admin

# Run with auto-reload (single worker!)
cd app && QUIZ_SECURE_COOKIE=0 ../.venv/bin/uvicorn main:app --reload --port 8765

Open http://127.0.0.1:8765. Static files are served with Cache-Control: no-cache so JavaScript and CSS edits appear immediately on refresh.

Where to customize behavior

Prefer .env and Admin UI for per-client branding

Keep one shared codebase for every school or client and store differences (name, logo, colors, registration, AI key) in .env and the Admin page so upgrades stay effortless.

What you want to changeWhere to edit
Any UI text in Bahasa Indonesia & Englishapp/static/js/strings.js (key → [Indonesian, English])
API error messages (both languages)MSG dictionary in app/main.py, ai.py, guard.py, admin.py, brand.py
Layout, typography, or default paletteapp/static/style.css (--teal-* and --amber-* CSS variables)
AI prompt rules & TOEFL reading instructionsbuild_prompt and build_reading_prompt in app/ai.py
Speed-bonus scoring formulapoints_for in app/main.py
Anti-cheat grace period (default 2.0 s)GRACE in app/guard.py
Limits (max players, upload sizes, material caps)Constants at the top of app/main.py (MAX_PLAYERS, MAX_UPLOAD) and app/ai.py (MAX_FILE, MAX_MATERIAL)

Running tests

Run the full test suites before cutting a release or deploying customizations:

bash
# 1. API & logic test suite (accounts, quizzes, games, AI, anti-cheat, wheels, branding)
.venv/bin/pytest -q

# 2. Full browser E2E test with Playwright (teacher + students through a complete session)
PLAYWRIGHT=/path/to/node_modules/playwright/index.mjs tests/run_e2e.sh [screenshot-dir]

GitHub Actions (.github/workflows/tests.yml) automatically runs pytest -q and builds/boots the Docker image on every push and pull request.

Security & architecture notes

  • Password hashing: scrypt (N=16384, r=8, p=1) with random 16-byte salts and constant-time comparison.
  • Sessions: 32-byte random tokens stored SHA-256 hashed in SQLite, issued in HttpOnly, SameSite=Lax, Secure cookies (30-day lifetime).
  • CSRF protection: Every mutating /api/* request requires the custom header X-Quiz: 1, which browsers block cross-origin without CORS preflight.
  • WebSocket origin check: Live WebSockets validate Origin against Host.
  • Strict headers: Content Security Policy (script-src 'self', frame-ancestors 'none'), X-Content-Type-Options: nosniff, Referrer-Policy: same-origin, plus HSTS via Caddy/Nginx.
  • Unprivileged container: The Docker image runs as non-root user 1000:1000 with a single Uvicorn worker (--workers 1) so in-memory live game state stays consistent.
