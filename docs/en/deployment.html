Administration & Hosting

Deployment & Operations

Complete reference for environment variables, AI providers, custom starter quizzes, Nginx reverse proxy setup, nightly backups, restores, and safe updates.

Environment variables (.env)

Settings live in deploy/.env. Keep this file private (chmod 600 .env) because it stores your AI API key. Variables marked Admin UI serve as starting defaults and can later be changed on the Admin page without touching the server.

VariableDefault / ExampleAdmin UIDescription
DOMAINquiz.example.sch.idNoPublic domain name for Caddy automatic HTTPS
ADMIN_EMAIL, ADMIN_NAMEadmin@example.sch.idNoFirst admin created by ./install.sh if no admin exists yet
QUIZ_SITE_NAMEQuizYesSite title in header and browser tab
QUIZ_ORG(empty)YesOrganization name
QUIZ_COLOR_PRIMARY#0f6b5fYesPrimary brand hex color (derived shades computed automatically)
QUIZ_COLOR_ACCENT#f0b429YesAccent hex color
QUIZ_REGISTRATIONopenYesopen or closed
QUIZ_DEFAULT_ROLEstudentYesRole for new sign-ups: student or teacher
QUIZ_SEEDoff (in .env.example)NoSet on to load starter JSON quizzes from QUIZ_SEED_DIR into the public library once
QUIZ_SEED_DIR/app/seedNoCustom directory of *.json starter quizzes mounted into the container
QUIZ_AI_URLhttps://api.deepseek.com/v1NoOpenAI-compatible API base URL
QUIZ_AI_MODELdeepseek-v4-flashNoModel identifier sent to /chat/completions
QUIZ_AI_KEY(empty)NoBearer API key; leaving empty disables AI features cleanly
QUIZ_AI_SOCKET(empty)NoOptional Unix domain socket path for a host Hermes Agent API server

After editing deploy/.env, apply changes by running ./install.sh or docker compose up -d.

Configuring AI providers

Any provider exposing an OpenAI-style /chat/completions endpoint works out of the box:

ProviderQUIZ_AI_URLExample QUIZ_AI_MODEL
DeepSeekhttps://api.deepseek.com/v1deepseek-v4-flash
OpenAIhttps://api.openai.com/v1gpt-5-mini
OpenRouterhttps://openrouter.ai/api/v1deepseek/deepseek-chat

All requests are billed to QUIZ_AI_KEY. Built-in per-teacher throttling (5 requests / 5 min and 40 / day) prevents runaway usage.

Loading custom starter quizzes

Export any quiz as JSON from its quiz page, place one or more .json files in a host folder, mount that folder into the container (e.g. /seed), and set QUIZ_SEED=on and QUIZ_SEED_DIR=/seed. Each filename stem is imported once as a read-only public quiz that any teacher can host or duplicate.

Using an existing Nginx server instead of Caddy

If your server already runs Nginx on ports 80/443:

  1. Expose the quiz container on localhost only

    In deploy/docker-compose.yml, add ports: ["127.0.0.1:8000:8000"] to the quiz service and start only the app container:

    bash
    docker compose up -d --build quiz
  2. Configure Nginx using deploy/nginx.example.conf

    Make sure you preserve three critical blocks from the example config:

    • location /ws/ — WebSocket upgrade headers and proxy_read_timeout 3h so live games stay connected.
    • location /api/ai/ — client_max_body_size 51m (for 50 MB PDF/PPTX uploads) and proxy_read_timeout 300s.
    • Generous rate-limit burst (burst=600 nodelay) because an entire classroom often shares one campus NAT IP address.

Backups & disaster recovery

All persistent data lives inside the Docker volume quiz_quiz-data (mounted at /data inside the container): quiz.db, uploads/, brand/, and backups/.

Run a live backup

manage.py backup uses SQLite's online backup API (safe while the site is running), bundles quiz.db, uploads/, and brand/ into a timestamped .tar.gz archive in /data/backups, and automatically keeps the latest 14 archives.

bash
# Run a manual backup
docker compose exec quiz python manage.py backup

# Copy backup archives off the server
docker compose cp quiz:/data/backups ./backups

Schedule nightly backups with cron

cron
0 2 * * * cd /path/to/quiz-platform/deploy && docker compose exec -T quiz python manage.py backup

Restore from a backup archive

bash
cd /path/to/quiz-platform/deploy
docker compose stop quiz
docker compose run --rm -v "$PWD/backups:/b:ro" quiz \
  tar xzf /b/quiz-YYYYMMDD-HHMMSS.tar.gz -C /data
docker compose start quiz

Updating & viewing logs

bash
# Follow live application logs
docker compose logs -f quiz

# Update to the latest release (preserves all data in quiz_quiz-data)
cd /path/to/quiz-platform
git pull
cd deploy && ./install.sh

Update outside class hours

Updating keeps all database records, uploads, and branding intact, but restarting the container interrupts any live game currently in progress (answers already submitted are kept).

Pre-handover checklist (schools & clients)

  • License: Quiz Platform is MIT-licensed; retain the copyright notice in the codebase.
  • Data privacy: Student names, emails, and scores remain on the institution's server. Agree in writing on retention policy and who holds Admin access.
  • Admin recovery: Confirm at least one administrator has changed the initial password and knows how to reset forgotten user passwords.
  • Backups verified: Confirm nightly cron backups are running and periodically copied off-server.
